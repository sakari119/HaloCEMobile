# Trevor web crash on Galaxy S24

The user ran the GitHub Pages web port in Chrome 154.0.8037.92 on a Galaxy S24 with Android 16. The game image was `Halo - Combat Evolved (USA).xiso`. The user saw a page crash during campaign play. An Android Debug Bridge (ADB) log captured one repeat on 2026-10-02.

At 00:27:32, Chrome reported `GL_INVALID_OPERATION: glBlitFramebuffer: Blit feedback loop: the read and draw framebuffers are the same.` In `port/linux/src/d3d8_gl.c`, `framebuffer_get()` binds `GL_FRAMEBUFFER` on a cache miss. `D3DDevice_Present()` previously bound draw framebuffer 0 before that call. A cache miss replaced both bindings with the read framebuffer. The fix gets the read framebuffer first, then binds draw framebuffer 0.

At 00:27:53, Android's low-memory killer started to reclaim background processes. At 00:28:04, it killed a foreground Chrome sandbox process and Chrome itself. Chrome then closed. The log supports memory pressure as the direct cause of this page closure. It does not show which allocation caused the pressure. The graphics error happened about 30 seconds earlier, so its role in the memory event is unknown.

The web build starts with a 0x88000000-byte WebAssembly memory, about 2.125 GiB. This is an address-space requirement. The captured log does not show how many of those pages were resident. Do not claim that the full allocation was in physical RAM.

The raw 44 MB ADB log is in ignored `Agent_Test_Output/web-crash-logcat-20261002-002639.txt`. It can include private device data. Do not commit or share the raw file. For the next phone test, arrange a slot with the other project agent. Record memory use over time for Chrome, its sandbox process, and the system while the same scene runs.
